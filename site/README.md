# ALI.OS Companion Portal

This is the **interactive website portion** of Ali Nikan's sci-fi × gaming GitHub profile. The profile README itself only uses GitHub-safe Markdown, HTML, and SVG assets. Browsers do not run embedded JavaScript in GitHub README pages.

## Preview the actual companion portal locally

The companion portal requires no build step or dependencies. From the repository root:

```bash
cd site
python3 -m http.server 4173
```

Open **http://localhost:4173** in a current desktop or mobile browser on the same machine.

The core portal runs entirely with **HTML, CSS, and JavaScript**. The local project guide, dynamic constellation, project filters, Starfall mini-game, clocks, season switcher and navigational links work without an API key. The guestbook reader will attempt to fetch public approved GitHub Issues, but it safely shows a fallback when there are none or the API is unavailable. The soundtrack viewer reads opt-in metadata from the public `main` branch so its content can update without redeploying the static site.

## Deployment options

### Option A: GitHub Pages (free static portal)

Use the prebuilt workflow `.github/workflows/pages.yml`. After **review and merge**, enable GitHub Pages in **Settings → Pages** with **Source: GitHub Actions**. Then run the `Publish ALI.OS Companion Portal` workflow. The canonical address should be:

`https://alinikan.github.io/alinikan/`

That address will **not work until deployment succeeds**. GitHub Pages cannot execute `site/api/ask.js`; the project guide stays in local, non-AI mode. The deployment workflow excludes the API source from the published website.

### Option B: Vercel (supports the optional server-side AI adapter)

Deploy the repository with **Root Directory set to `site`**, framework preset **Other**, and no build command. Set up preview deployments from the review branch before promoting anything to production.

To enable model-backed answers:

1. Create the Vercel project and verify the exact Git repository/branch and preview domain.
2. Add `OPENAI_API_KEY` in Vercel's protected server-side environment configuration. Do **not** commit it or expose it to browser code.
3. Optionally set `ALIOS_OPENAI_MODEL` to a reviewed model identifier available in your account (the fallback is `gpt-4.1-mini`).
4. **Before exposing the public endpoint**, enable platform rate limiting/WAF and low spending limits. The current function validates input, caps output, checks same-origin requests and avoids storing responses, but these safeguards **do not replace abuse protection**.
5. Add `<meta name="alios-ai-endpoint" content="/api/ask">` to `site/index.html`, rebuild, and test on the preview deployment. Without that meta tag, the browser always uses the safe local guide instead.
6. Verify the API responds accurately using only the curated public project list. Expand project knowledge carefully and never index private repositories without explicit permission.

The server function returns `503` when its API key is missing, and the browser falls back to local project answers.

## Guestbook moderation

GitHub Issues are the database, so there's no additional server or secret. After merge, run **Prepare guestbook labels** once to create the approval labels.

- Visitor opens the `Visitor transmission` issue form after the template is merged.
- The issue receives `guestbook-pending` by default.
- To approve, repository owner reviews content and adds the **`guestbook-approved`** label.
- The companion portal only reads publicly approved issues from GitHub's API. It uses `textContent` to render visitor text, not untrusted HTML.
- To unpublish a transmission, remove the approved label (and close/edit the issue as desired). Cache may delay immediate removal for visitors.

**Important:** GitHub users need to sign in to create an Issue. They should not include personal information, private contact data, passwords, or other sensitive details. All submitted issues are public from the moment of submission, whether approved for the site or not.

## Now Playing privacy and activation

Nothing is connected by default. The site displays **Not connected**, and `now-playing.json` contains `enabled: false`.

If you deliberately want to publish your listening activity, add:

- Repository variable `LASTFM_USERNAME` (public username).
- Repository secret `LASTFM_API_KEY` (never reveal in source or logs).

Run **Refresh optional Last.fm soundtrack station** from Actions. It uses the Last.fm recent-tracks API and commits a small, public, sanitized JSON record. It refreshes every six hours, so the UI says **Recently played** unless a very fresh update explicitly reports playback. GitHub raw-file caching may briefly delay updates or opt-out visibility. This is not a real-time streaming player.

For immediate opt-out, change `site/now-playing.json` back to `enabled: false` and remove both settings; don't wait for the next schedule.

## Performance, accessibility and trust

- No browser third-party analytics, cookies, autoplay audio, or external JS libraries.
- Reduced-motion CSS disables animations. Canvas background also respects the preference.
- Keyboard-compatible navigation and project controls; Starfall supports keys and pointer/touch.
- Visitor questions are handled locally unless the optional protected model API is explicitly configured.
- Guestbook submissions stay on GitHub, not in an anonymous form or browser service.
- All assets and workflows can be reviewed in the same PR before anything merges.

## Why some features aren't live yet

This is a **draft feature branch**. GitHub Pages, GitHub Issues templates, and default-branch GitHub Actions need the relevant deployment and activation steps before public functionality is available. No live service is claimed unless actually verified.
